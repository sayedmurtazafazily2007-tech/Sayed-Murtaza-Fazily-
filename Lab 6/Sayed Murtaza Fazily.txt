4. CONTROLLER (app/Http/Controllers/AuthController.php)
--------------------------------------------------
<?php

namespace App\Http\Controllers;

use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\Hash;

class AuthController extends Controller
{
    public function register(Request $request)
    {
        $data = $request->validate([
            'name' => 'required|string|max:255',
            'email' => 'required|email|max:255|unique:users,email',
            'password' => 'required|string|min:8|confirmed',
        ]);

        $user = new User();
        $user->name = $data['name'];
        $user->email = $data['email'];
        $user->password = Hash::make($data['password']);
        $user->save();

        return redirect()->route('login')->with('success', 'Account created. Please log in.');
    }

    public function login(Request $request)
    {
        $credentials = $request->validate([
            'email' => 'required|email',
            'password' => 'required|string',
        ]);

        $accepted = Auth::attempt($credentials);

        if (!$accepted) {
            return back()->withErrors([
                'email' => 'Email or password is incorrect.',
            ])->onlyInput('email');
        }

        $request->session()->regenerate();

        return redirect()->intended(route('dashboard'));
    }

    public function logout(Request $request)
    {
        Auth::logout();
        $request->session()->invalidate();
        $request->session()->regenerateToken();

        return redirect()->route('login');
    }
}


5. CONCEPTUAL QUESTIONS & ANSWERS
--------------------------------------------------
1. Why do we use Hash::make() when saving a new password?
Answer: We use Hash::make() to securely hash passwords before storing them in the database. Storing plain-text passwords is a major security risk. Hashing is a one-way transformation that ensures passwords cannot be reverse-engineered or exposed, even if the database is compromised.

2. How does auth middleware protect the dashboard?
Answer: The auth middleware checks whether the incoming HTTP request is made by an authenticated (logged-in) user. If the user is authenticated, it allows the request to proceed to the dashboard. If the user is a guest (not logged in), the middleware intercepts the request and automatically redirects them to the login page.

3. What does @csrf add to a form?
Answer: The @csrf directive generates a hidden HTML input field containing a unique, secret CSRF token associated with the user's current session. When the form is submitted, Laravel verifies this token to protect the application from Cross-Site Request Forgery (CSRF) attacks, ensuring the request genuinely originated from the authenticated user within the application.
